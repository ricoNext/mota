# 魔塔（Magic Tower）设计说明

日期：2026-10-19  
状态：待用户审阅

## 目标

自研一款经典「算数爬塔」玩法的《魔塔》：

- **简单模式**：复刻约 21 层体验（童年步步高词典向）
- **困难模式**：复刻约 50 层体验（日文原作 *Tower of the Sorcerer* / 魔法の塔 向）
- **发布路径**：先做网页；架构预留迁到**微信小程序**
- **第一版成功标准**：2～3 层可玩，包含移动、钥匙与门、战斗、存读档

对外传播时使用自绘素材与自创或获授权的地图数据；玩法规则可沿用经典魔塔机制，不把未授权的完整原作关卡当作上架内容。

## 技术路线

采用 **TypeScript 纯逻辑核心 + Canvas 薄渲染层**（不选 Taro/uni-app 作为第一版载体，也不以 HTML5 魔塔开源仓库为直接分叉基线）。

## 架构

三层分离：

1. **`core/`** — 纯 TypeScript，无 DOM。状态、移动合法性、钥匙/门、战斗结算、商店、楼层切换、存档序列化。以单元测试覆盖。
2. **`data/`** — JSON 数据包。`easy/` 与 `hard/` 分别承载简单/困难模式的地图、怪物表、道具表。引擎只读数据。
3. **`adapters/`** — 薄渲染与输入。先实现 `web/`（Vite + Canvas + 旁路 HTML 状态面板）；日后增加 `wechat/`，复用同一 `core` 与 `data`。

主循环：输入 → `core.step(command)` → 新状态 → adapter 重绘。

## 核心玩法与数据模型

### 地图

每层为二维网格。格子类型包括：地板、墙、上下楼梯、黄/蓝/红门、钥匙、血瓶、攻/防宝石、怪物、NPC/商店、其他道具。地图 JSON 存格子 id 与表引用；数值定义在独立表中，便于两套难度共用引擎。

### 玩家状态

楼层、坐标、生命、攻击、防御、金币、黄/蓝/红钥匙、背包、已触发事件标记。每一步产生明确的新状态，便于撤销与存档。

### 战斗

无经验值、无随机数。按攻防差进行回合式结算。第一版策略：**预估伤害后，打不过则不可踩上怪物格**（或等价的「禁止无效硬撞」），避免无提示秒死。

### 门与钥匙

对应颜色钥匙数量 ≥ 1 时扣一把并开门（格变为地板）；否则不可进入。

### 商店

用金币兑换攻/防/血；价格与增量全部数据驱动。

### 存档

序列化玩家状态 + 地图可变部分（已开门、已拾取等）为 JSON。网页使用 `localStorage`；小程序阶段改为对应存储 API。第一版提供 1～3 个存档槽。

## 渲染、输入与质量

### Web 适配器（第一版）

- Vite + TypeScript
- Canvas 绘制网格（可用色块或简单像素图）
- HTML 面板显示血/攻/防/金币/钥匙
- 键盘方向键移动；可选点击相邻格（为触控预留）

### 输入命令

适配器仅发出：`Move(dir)`、`Confirm`、`Cancel`、`Save(slot)`、`Load(slot)`。规则全部在 `core`。

### 失败与边界

撞墙、缺钥匙、打不过等：返回未变更状态 + 原因码，由 UI 短暂提示。存档损坏时读档失败并提示，不中断应用。

### 测试

Vitest 覆盖 `core`：遇墙、开门、战斗公式、拾取、换层、存读档往返。可选：样板关预设路径通关脚本。不测 Canvas 像素。

### 明确不做（第一版）

地图编辑器 GUI、联机、必选音效/复杂动画、完整 21/50 关卡数据灌入、微信登录、第一版引入 Taro。

## 第一版交付物

- 可本地运行的 Web 工程
- `core` + 样板 2～3 层 `data`
